# よろず便利商店 Web商品棚

GitHub Pagesで公開する静的商品棚です。見た目は `index.html`、商品情報は `data/products.json` に分離しています。

## AI側の標準更新フロー

1. 商品候補を受け取り、正規の商品・ショップ・画像を確認する。
2. Cloud Browserの楽天アフィリエイトへアクセスする。ログイン済みなら商品検索→商品リンク作成→「短縮URL」選択までAI側で行い、`https://a.r10.to/...` を取得する。
3. ログイン・2FA・CAPTCHAが表示された場合だけオーナーへ認証操作を依頼し、認証後はAI側の操作へ戻る。認証情報は要求・保存しない。
4. `scripts/add-products.mjs` で商品を追加する。処理不能な1商品はスキップし、残りを継続する。
5. `npm run validate` で必須項目、URL形式、重複を検査する。
6. feature branchへ反映し、差分を確認してからmainへ反映する。
7. GitHub Pages反映後に `npm run check:live` を実行する。
8. 公開ページのPC幅・スマホ幅を確認する。

重大な誤り（商品候補の取り違え、不正なアフィリエイトURL、権利不明画像、既存サイト破損の可能性）は自動スキップせず停止します。

## 楽天短縮URLの取得

2026-08-29に、WorkのCloud Browserでログイン済みセッションを再利用し、既存掲載商品について次の操作が可能であることを実機確認済みです。

1. 楽天アフィリエイトの商品検索で商品名を検索
2. 商品名・ショップを照合
3. 「商品リンク作成」を開く
4. リンクタイプ「短縮URL」を選択
5. 生成された `https://a.r10.to/...` を商品データへ使用

商品が複数候補に分かれて正しい商品を確定できない場合は、その商品だけ保留します。ログイン状態が切れている場合は認証地点で停止し、オーナーの認証完了後に続行します。

## 追加商品JSON

単品オブジェクトまたは配列を受け付けます。

```json
{
  "name": "商品名",
  "short": "紹介文",
  "image": "https://正規画像URL",
  "url": "https://a.r10.to/短縮コード",
  "shop": "楽天市場"
}
```

実行例：

```sh
node scripts/add-products.mjs /tmp/new-products.json
npm run validate
```

`url` は短縮URLのほか、楽天ウェブサービスが正式に返す `https://hb.afl.rakuten.co.jp/hgc/...` 形式にも対応しています。
