# Web商品棚 WORK-ORDER｜45→50商品＋公開ページ自由検品
日付：2026-09-28
発注元：Web商品棚運用室

## 目的
mainの45商品を基準に、商品選定基準を使って新規5商品を追加し、50商品到達後にGitHub Pages公開ページを実ブラウザで自由検品する。
成功条件は「作業PR作成」ではなく、mainが50商品になり、公開反映と自由検品まで完了していること。

## 開始前に必ず確認
- main の `data/products.json` が45商品であること
- 現在カテゴリ数：gadget 16 / desk 12 / home 9 / outdoor 8
- 直近作業PR #54（40→45）の実績
- 既存45商品との商品名・役割・URL重複
- 可能なら開始時のWork残量（5時間枠／週間枠）

## 商品選定基準
以下を総合して新規5商品を選定する。
- よろず便利商店らしい「ちょっと便利・ちょっと面白い」
- 既存棚と役割が被りすぎない
- 画像だけでも用途が伝わりやすい
- Instagram／カルーセルで紹介しやすい
- 価格が極端すぎない
- アフィリエイト導線が安定
- カテゴリ偏重を避ける（現状gadget 16が最多なので、同等ならhome／desk／outdoorを優先）
- 各商品の選定理由を1行で説明できる

候補探索は既存提携先・既存導線を優先してよいが、既存45商品の類似品を機械的に増やさない。

## 実行
1. 新規5商品を選定。
2. 各商品について、実ブラウザで現行販売ページを確認。
3. 商品名・用途・商品画像・販売状態・アフィリエイト／商品リンクを確認。
4. 推測スペックは禁止。確認できた内容だけでshortを書く。
5. 既存45商品との商品名・URL・役割重複を確認。
6. `data/products.json` に5商品のみ追加。原則として既存45商品は変更しない。
7. JSON、必須項目、カテゴリ、URL、重複、既存validate、必要なCIを実行。
8. 作業PRを作成し、差分が想定どおりか自己確認。
9. 下記安全条件を全て満たす場合、この発注に限りWork自身でmainへマージしてよい。
10. マージ後、mainが50商品であることを再確認。
11. GitHub Pagesの公開反映を確認し、公開ページを実ブラウザで自由検品する。

## 自動マージ安全条件
- 追加は新規5商品のみで、意図しない既存商品変更がない
- 変更範囲が想定内
- 画像5点が読み込み可能
- 商品／アフィリエイトリンク5件が対象商品へ正しく対応
- 必須項目・カテゴリ・URL・重複検査が正常
- validate／CI等が正常
- 課金・購入・契約・権限変更等の新規判断が不要
- 不明情報を推測で補っていない
- 想定外差分や重大な警告がない

一つでも満たさない場合はマージせず安全停止。

## 50商品到達後の公開ページ自由検品
チェックリスト消化だけでなく、人間の初見客として違和感も探す。
最低限：
- 50商品が表示される
- 全商品画像の明確な読み込み異常がない
- カテゴリ絞り込みと件数が整合
- 商品リンク構造に異常がない
- サイト由来のJavaScriptエラーがない
- PC／スマホで致命的な表示崩れがない
- 商品数や固定文言に更新漏れらしい食い違いがない
- 新規5商品の並び・説明・画像に違和感がない
- その他、チェックリスト外でも「客として変」と感じる点を自由に探す

既知の軽微な改善候補（棚37表記、Vacuum Proのutm_source=chatgpt.com、OGP/X/canonical/favicon等）は、今回の5商品追加へ無断で混ぜて修正しない。自由検品で現状を再確認し、重大化していなければ報告のみ。
重大な不具合を発見した場合は、今回追加によるものなら修正して再検証。既存由来で修正範囲が広がる場合は安全停止して報告。
